# UniHub v0.4.8

注册限流与重试状态修复。

## 变化

- 注册首次被限流时，服务端返回 429、`Retry-After` 和相同的 `retry_after` 整数秒数，指向当前每小时固定窗口的结束时间。
- `registration_not_started: true` 只说明服务端串行判定时当前 client/key 没有已保存的注册操作。该标记不能清除此前 UNKNOWN 的不确定状态。
- 同一 client/key 的注册判定使用 PostgreSQL 事务锁串行执行；已有操作在限流前重放并对账，不重复创建账号。UNKNOWN 意图持久化后释放判定锁，再调用身份提供方。
- 注册限流存储错误返回 503，避免伪装为用户额度耗尽。原有每产品/IP 每小时 3 次、跨产品/IP 每小时 12 次限额保持不变。
- 页面根据明确的首次未开始标记展示倒计时并恢复后续提交；此前 UNKNOWN 请求继续沿用原幂等键。
- 可信源 IP 传递由部署站点显式启用，继续只信任指定的回环代理输入。身份提供方和现有认证方式保持当前规则。

## 后端验证

- 在真实本地 PostgreSQL 的独立临时 schema 中验证注册限流：初次 429 不保存注册记录、不联系身份提供方，响应头与 JSON 秒数一致且在 1–3600 范围内，并指向实际固定窗口结束时间。
- 同键并发、UNKNOWN 在额度耗尽后的重放、单连接池对账、限流存储错误、秘密不持久化和现有代理头伪造拒绝测试通过。
- `go test -race ./internal/identityapi -count=1 -timeout=2m` 通过。
- `go test -race ./... -count=1 -timeout=180s` 在配置隔离 PostgreSQL、真实本地 Formance 和 LLMRouter 网关夹具后通过：471 个测试及子测试通过，无测试用例跳过；3 个包无测试文件。网关提供方响应和身份校验仍为受控夹具，不作为真实支付或供应商验收证据。

前端、部署源 IP 和最终发布包的验证由合并后的发布验收记录补充；本文的后端测试不替代生产注册或代理链路读回。

## 边界

本次发布不扩大注册限额，也不改变认证方式。UniHub 充值与会员资金仍为 **sandbox**；真实商户收款/激活、供应商账单对账和既有模态边界沿用 v0.4.7 的验收记录。SDK 保持 `private:true`，不发布至 npm。发布包不包含生产配置或凭据。
