# UniHub v0.4.36

SuperWagie 使用 LLMRouter 原生 Key 产生的消费归属 LLMRouter；普通产品查询仍按 SuperWagie 来源隔离。本版增加显式的只读权限，供已登记客户端读取这部分消费。

- 新增 `usage:llmrouter`，复用 `/v1/accounts/{account}/model-pool/calls`、调用详情和 `/model-pool/usage/summary`。权限仅覆盖当前付款账户、登记实例内的 `origin_product_id=llmrouter`、`source=product_runtime` 记录。
- 访问者须具有当前账户的 `owner` 或 `billing_admin` 角色，报表事务内再次核对；其他产品、其他实例、托管模型记录及无权账户保持隔离。普通 `/calls` 和 `/usage/summary` 继续按已验证产品来源查询。
- 来源范围加入分页游标与响应 `scope.source` / `filter.source`。SDK 沿用既有 model-pool 方法，客户端登记工具支持新 scope。
- 金额保留整数串；`CNY/6`、`LR_QUOTA/0` 等资产分别展示，原始实扣与确认返还分开。原生用量未提供可信通用 token 明细时保持不可用状态。

已完成以下验证：

- 在隔离的真实 PostgreSQL、Formance 环境运行 `httpapi`、`billing`、`products` 三包 race 回归：383 项通过、0 失败，首轮 5 项需显式开启的验收跳过。
- 使用冻结源码及跨仓 fixture 修正显式补跑：财务重放与新账户隔离 3 项、LLMRouter 原生额度 1 项、统一现金 1 项，均通过且无失败或跳过。
- 首轮其余 3 个 gateway 验收随后显式补跑，共 7 项通过、0 失败、0 跳过；其中 wire operation 使用内存账本 fixture，另两组使用真实 Formance。上述跨仓与 gateway 测试均启用 race 检查。
- SDK 17 项、客户端登记工具 14 项、SDK 类型检查、Go 构建及 OpenAPI 契约检查通过。

测试供应商为受控 HTTP/TLS fixture，数据库与真实账本均与生产隔离；未发起真实支付、外部供应商调用或生产写入。生产部署回读另行验证，发布附件不包含私有运行日志。

启用时只为目标已登记客户端增加 `usage:llmrouter`，保留现有身份策略、密钥、钱包和产品计价。此次发布不代表真实支付、生产模型调用或完整生产业务验收通过。
