## 执行证据

最终源代码执行 `make test-integration`，所有有测试的包均通过 `-race -count=1 -timeout 90s`，未设置跳过集成环境。实际使用隔离 PostgreSQL schema 和真实 Formance v2.4.16。`go vet ./...`、`make build`、`git diff --check` 通过。

关键用例：相同邮箱不同 subject 不合并、跨账户访问拒绝、受邀人及邀请者权限校验、owner 提升需接受、最后 owner 并发保护、个人账户不能添加其他成员、错 token purpose/issuer/audience/签名/过期均拒绝；重复回调只入账一次，错误商户/金额/币种/终态不落收款记录，同一支付交易不能支付两个订单。

真实 Formance 集成测试：充值 100 元后并发两笔 80 元划拨，仅一笔成功，统一钱包保留 20 元；重建业务 service 并重放已完成操作不再次扣款。响应丢失后的 UNKNOWN 核实、权限撤销与提交锁的并发场景由真实 PostgreSQL + 可控账本测试替身验证；没有把测试替身结果宣称为真实网络故障注入验收。

实际部署验证：固定版本 PostgreSQL、Formance、Casdoor 运行于本地；初始化脚本重复执行保留原凭据。真实 API `/healthz` 返回 200；不带 token 的 `/v1/me` 返回 401。

实际浏览器验证：本地测试 Alice 登录 Casdoor，通过授权码 + PKCE 回调和 token 交换，真实签发的 access token 被 UniHub `/v1/me` 接受，返回 200 与 Alice 身份。该流程发现并修复了 Casdoor 初始化表单缺少 Login button 的问题；没有修改测试用户密码或轮换密钥。

随后用该真实登录令牌调用正在运行的 API，完成以下 **sandbox 模拟资金** 验收：

| 操作 | 结果 |
| --- | --- |
| 重复创建 100 元充值单 | 同一 order ID |
| 重复确认模拟付款 | 同一 operation ID，只入账一次 |
| 向 SuperWagie 划拨 80 元 | APPLIED |
| 再向 AgentWiki 划拨 80 元 | REJECTED，余额不足 |

上述余额仅存在于本地 sandbox，没有任何真实商户收款。

## 审查修复

独立审查及针对性回归修复了：用户转账幂等键与内部充值键冲突、一个 UNKNOWN 账户堵塞其他账户恢复队列、失权邀请者的旧邀请阻塞重新邀请、数据库清理操作缺少截止时间。迁移 003/004 保留既有数据并升级约束。

最后一轮独立审查未发现新增可操作缺陷。权限撤销边界明确为在账户锁内进入 SUBMITTING；原操作后续仍可核实结果。UNKNOWN 不因一次查询为空就自动判失败；这优先避免错误补偿，但需要运维处理长期异常。
