# 首版设计一致性审查

审查范围：`CONTEXT.md` 与 `docs/superpowers/specs/2026-10-24-unihub-design.md`。只做文档审查，没有运行平台或验证支付。

| 发现 | 修订 |
| --- | --- |
| 同月连续升级可能撞发放唯一键 | 基础、升级、加量包分别使用稳定唯一键；升级保持原锚点、同期期末过期、报价绑定版本 |
| 年付最后一期可能越过已付服务终点 | 批次使用半开区间，并截于 paid_through；补跑不延长有效期 |
| 逻辑调用和供应商重试未分开，费率权威不清 | logical_call_id 与 attempt_id 分离；调用方幂等键绑定摘要；UniHub 已发布费率版本与标准化用量复算 |
| 退款只锁订单，未覆盖在途额度消费 | 先冻结来源批次，处理在途预占；购买回钱包与充值回原支付交易分开 |
| 批次数量可能成为第二套余额 | Formance 分录为数量权威，业务库只保留可重建投影；补齐失效量与批次守恒公式 |

已确认业务规则保持不变：个人/团队隔离；每产品现金钱包；统一钱包授权补款；llmrouter 统一提供模型并消耗同账户额度；套餐包含额度；不足时升级或买包；月度不结转、年付逐月发放。

商品价格、额度规格、团队席位、加量包有效期及退款条件属于商家配置。实际销售前须发布明确配置；未发布商品不能收款。架构设计中的建议默认值不冒充已确认商业政策。
