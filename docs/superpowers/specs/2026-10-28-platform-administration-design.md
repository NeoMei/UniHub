## 2. 推荐架构及备选

**推荐：现有 UniHub Web 增加独立“平台管理”区域，共用登录，使用独立平台权限和 `/admin/v1` API。** 保留个人/团队工作区。复用账户、产品授权、账务、模型服务的领域事务，补全跨用户查询与受控管理操作。

备选是独立部署管理前端，共用同一后台接口。优点是独立发布、可设置单独网络边界；代价是第二套前端部署、登录回跳和版本协调。当前已有 React 控制台和浏览器会话边界，推荐第一项。管理路由与模块仍保持独立，未来可拆前端。

只调整 `USER_ADMIN_IDS` 可恢复已有简版用户管理，但不能满足目录完整、团队、财务、审计和运维管理的要求，不作为本次完整交付。

### 页面与导航

- 账户工作区继续提供现有个人/团队功能；有管理资格的用户获得“平台管理”入口。
- 管理区域顶栏明确显示“平台范围”和当前平台角色，不显示团队 owner 作为平台权限。切换付费账户不改变平台权限，平台操作也不改变当前付费账户。
- 使用稳定路径，例如 `/admin/users`、`/admin/users/{id}`；支持刷新、浏览器前进后退和直接链接。未经授权访问路径，服务端仍拒绝数据与写操作。
- 每页区分加载、空数据、403、401、未配置、依赖不可用；提供重试和请求编号。没有数据不能替代查询失败。
- 常规列表有搜索、筛选、排序、总数、分页、刷新和详情入口。操作成功必须读回服务端状态；版本冲突提示刷新比较。
- 导出提供用户/账户目录、订单、调用和审计的筛选后 CSV，单独校验导出权限、限制规模、转义公式单元格并记录审计；不导出秘密或完整调用内容。

以下不是用占位按钮替代：创建/邀请、密码重置、资料修改如果依赖身份提供方能力，需要实现服务端适配、失败与未知结果状态。恢复凭据只交付用户已有的、已验证的渠道，后台不返回可接管既有账号的激活/重置链接。无已验证渠道时明确显示“尚未具备自助恢复条件”，不能放宽验证或给管理员返回秘密。管理员可创建待激活身份；用户完成联系渠道验证和密码设置之前无法登录。实际邮件发送是明确的用户动作；开发验收采用本地通知接收器，不向真实用户发送通知。

不在本次范围：新的真实支付渠道、自定义角色设计器、营销群发、供应商密钥/服务器凭据编辑、原生产品用户/余额迁移、管理员模拟登录、任意改余额、删除财务历史。订阅任意赠送/改期也不伪装成订单或直接改数据；需要独立的权益调整业务设计。

## 4. 平台权限与引导

平台角色归属于中央用户 UUID，和团队成员、产品角色、OIDC 全局 `isAdmin` 分离。首版内置固定角色及明确权限集合，不做任意表达式授权。

| 能力 | 超级管理员 `super_admin` | 用户管理员 `user_admin` | 财务管理员 `finance_admin` | 审计员 `auditor` |
| --- | --- | --- | --- | --- |
| 用户目录/资料/产品角色 | 读写 | 普通目标读写；产品特权角色由超管授予 | 定位账户所需的基本身份只读 | 只读 |
| 启停/邀请/重置/撤销用户会话与绑定 Key | 允许 | 允许，目标有平台管理角色时拒绝 | 不允许 | 不允许 |
| 团队目录/成员支持处理 | 读写 | 目录只读、名称修改及普通 member 邀请/移除；不能调整高权限成员 | 账务定位所需关系只读 | 只读 |
| 平台管理员授予与撤销 | 允许 | 不允许 | 不允许 | 不允许 |
| 全平台资金/订单/订阅/调用/预算 | 读写受控操作 | 仅非财务关联摘要；不展示金额 | 读写受控操作 | 只读 |
| 商品、费率、退款复核、账单配置 | 允许 | 不允许 | 允许 | 只读 |
| 产品安全配置发布 | 允许 | 不允许 | 不允许 | 只读安全摘要 |
| 审计与运行状态 | 全部脱敏读取 | 用户/团队/授权及自己的操作 | 财务相关及自己的操作 | 全部脱敏读取 |
| 导出 | 各已授权读取域 | 用户/账户基础目录 | 财务及调用 | 审计与各只读域 |

表中描述单独角色的能力。多个角色取权限并集，先判定实际 action 所需权限和受保护目标：平台管理员的身份/联系方式/状态/恢复/会话/Key/产品特权变更都要求超管权限；超管兼有 user_admin 时仍按超管权限执行，不被较低角色限制误拒绝。user_admin 不能把自己或他人提升为团队 owner/admin/billing_admin，也不能撤销高权限成员；不能通过改联系方式后重置接管账号。用户自身无有效管理资格就不显示平台入口。普通用户、团队 owner/admin、产品管理员、产品 token、模型 Key、服务 token 都不能据此调用平台 API。

### 初次启用与兼容

1. 新增平台角色持久化与权限服务，移除“用户管理必须有产品声明”的耦合；零接入产品也可管理中央用户。
2. `USER_ADMIN_IDS` 先作为持久化的“旧用户管理兼容资格”导入，只保留原目录、状态、产品授权权限，不升级为新 user_admin 或拥有财务权限的超管。该资格有独立来源/版本，且受新超管目标保护限制；升级为新内置角色必须显式授予。导入显式、幂等、可预览；完成受控切换后不再每次启动覆盖数据库授权，撤销不能被环境变量重新授予。
3. 首位超管通过受保护的部署命令，对读回确认的中央 UUID 显式引导；显示目标身份与权限范围，写入审计。不能使用“第一个注册用户”、邮箱匹配或 Casdoor `isAdmin` 自动提权。
4. 现有 `BILLING_OPERATOR_IDS` 与 `/ops/v1` 服务端工具保持原权限/认证；浏览器财务通过独立平台 finance 权限适配同一领域服务，不能把浏览器 Cookie 换成共享 operator token，不能伪造账单操作者。现有 operator 凭据不反向获得浏览器超管权限。
5. 超管不得通过日常界面自停用/自降权；对其他超管的降权、停用、重置在共享锁中检查，始终保留至少一名启用且可用的超管。批量启停不允许任何内置管理员或旧兼容资格目标。
6. 受控恢复命令支持重新指定已有中央 UUID；记录恢复原因/执行来源和结果，不创建通用密码，不关闭全站权限检查。

线上引导需核对现有管理员的实际身份并获得对应授权，不能凭本设计修改某个真实账户的权限。部署和权限变更分别读回验证。

## 5. 用户目录完整性与身份生命周期

### 两个来源明确展示

- “平台用户”查询中央数据库，具有稳定中央 UUID、账户及业务关系。
- “注册身份”只读查询当前 UniHub Casdoor 组织的身份目录，按已验证 `(issuer, subject)` 与中央记录关联；展示是否已建立平台用户。单独分页、单独总数、同步/查询时间与来源错误，不混算，也不把上游查询失败当成零用户。
- 注册身份目录排除服务身份、技术凭据和系统内置管理账号的日常编辑。对尚无中央 UUID 的普通身份，需要管理时先明确选择“建立平台记录”；然后执行同一套状态/恢复/授权流程，不另造一个可绕过中央检查的管理通道。已在上游被禁用的身份不能在建立平台记录时被默认启用。
- 外部原生产品的历史用户只在已有显式映射可用时显示关联摘要；没有受信读取适配时显示未接入，不扫描或写入其他产品数据库。
- 首次部署提供只读覆盖核对；查询目录不隐式创建个人账户或触发账务。允许将精确选中的注册身份显式建立平台记录，复用幂等身份创建，并记录操作人。禁止按同名/邮箱自动关联。
- 以现有用户为基线补齐时间字段：注册时间与中央建立时间分别展示；最近登录只由真实认证成功事件更新，不由列表访问更新。无法回填的历史字段显示“未记录”。

### 创建、资料与重置

- 管理员创建用户默认待激活普通身份、无可用密码、无平台/产品高权限、无赠送余额；可另行明确选择允许授予的产品角色。创建用幂等操作记录和精确 provider subject 读回；上游结果不明返回待核对，禁止再次创建。
- 邀请、激活及密码重置使用限时、一次性、绑定具体身份的随机凭据，服务端仅存摘要；用户自行设置密码，管理员不能读取密码或设置可长期共享的默认密码。
- 显示名称修改写入唯一权威身份提供方并读回，再更新中央显示；用户名/subject 不可编辑。邮箱修改单独执行验证流程，旧验证标记不能直接沿用，也不因修改邮箱合并用户。
- 提供安全重置适配：管理 API 只创建恢复请求并返回请求 ID/交付状态，用户在公开但限流的 `/auth/recovery` 页面验证一次性凭据、自行设密。兑换检查用途、目标 subject、有效期、单次消费和请求版本；跨库更新采用 durable intent/读回，结果不明不再次改密。当前 Casdoor 如缺少可复用的一次性流程，由受控服务端适配建立，不将后台填写新密码作为替代。
- 新身份管理适配必须独立校验生产能力：绑定当前 Casdoor 版本和 UniHub 组织，最小化服务端管理权限，验证资料/目录/激活/重置/撤销所需接口、日志脱敏、Origin 和限流。不能直接删除现有 `!Production` 判断即开放旧资料服务。能力检查失败时明确拒绝相应操作，核心交付验收须在目标部署等价配置中走通，不能只在开发模式演示。
- 重置成功必须撤销 UniHub 浏览器/用户 bearer 会话、产品登录会话和可继续刷新它们的旧授权，同时使身份提供方旧 SSO 会话不能无验证地重新签发新会话。实施前以当前部署的 Casdoor 验证更新密码、撤销会话/刷新授权及新登录的实际能力；缺少上游撤销机制时必须补适配并验收，不能把只删除 UniHub Cookie 当成完整重置。没有已验证恢复渠道的历史用户仅可自行登录后验证渠道，不能由普通用户管理员修改为自己控制的地址来恢复。
- 禁用用户不删除身份、账户或历史账务。首版不提供用户硬删除；保留合规删除为另行设计的流程。

### 停用、撤销和再次启用

- 本节的用户/产品登录会话均限定为该 UniHub `(issuer, subject)` 签发或派生的联邦登录会话、bearer 与刷新授权。独立的产品原生密码/SSO/Key 会话不因存在映射就纳入中央撤销；处理那些会话需产品自身权限及另行明确授权，不跨越成熟产品原有身份边界。
- 停用事务同时写全局状态/版本、撤销中央浏览器会话、推进该身份的凭据失效边界、永久撤销由该用户绑定的长期模型 Key、写审计；不能撤销同一团队其他用户的 Key。重新启用不复活旧凭据，须重新登录和重新签发 Key。
- “退出所有会话”撤销 UniHub 与产品浏览器/用户 bearer、可续接的刷新授权及上游 SSO；完成读回后显示成功。“撤销 API Key”是独立操作。单个会话可按安全引用撤销，列表不返回 session handle/hash、CSRF、原始 token。无法证明上游撤销时显示部分完成/待核对，不能声称所有设备已退出。
- 用户 bearer 校验必须验证签发时间并和失效边界比较；浏览器比较服务端创建时间/会话版本。缺失必要声明失败关闭。新签发通过，失效边界前旧凭据即使停用后再启用也不通过。
- 撤销产品权限只影响相应产品/实例的新请求；在每个业务入口实时复核。已开始的操作不声称回滚；异步新执行步骤重查权限。
- 已提交模型调用仍由可信服务按原用户/账户/产品绑定完成结算、释放预占和对账，不因用户停用留下悬挂资金；不会恢复用户的新调用权限。

## 6. 领域边界与安全操作

- 管理员跨用户读取通过专用查询服务完成，禁止给超管自动加入所有团队，禁止为普通 `/v1/accounts` 增加无条件旁路。
- 团队支持操作使用真实管理操作者和目标账户，不能传入 owner ID 冒充所有者。只有超管可以发起高权限角色邀请和所有权转移；目标必须启用并主动接受。接受时锁定账户，重新验证邀请来源的现行平台权限/用户状态与邀请版本，原子完成 owner 变更、邀请消费及审计。不能把现有只检查 invited_by 账户成员关系的实现直接拿来处理平台邀请；新增明确的 account/platform 授权来源，原账户邀请继续走原规则。
- 成员移除/降权仍保护最后一名 owner；若全局安全停用导致团队没有启用 owner，允许紧急停用用户，团队显示“所有者已停用，需恢复管理”。成员/所有权变更暂停，普通启用成员的既有使用和在途结算不因此改账或中断。超管通过邀请启用成员接管、对方接受后解除管理待恢复状态；不把用户自动加入团队或阻止紧急停用。停用预览列出受影响团队及其恢复入口。
- 钱包/额度数值以 Formance 为权威；商业记录以 PostgreSQL 为权威。若账本不可用，余额显示不可用/明确标注的缓存时间，不能用零或本地估算代替。跨账户余额不做逐行无上限远程请求。
- CNY 现金与模型额度分开显示；金额 API 继续使用带明确资产的十进制整数字符串，前端不转浮点。sandbox 充值、真实到账、订单金额、调用消费分别标明，不能混算收入。
- 退款只开放当前领域已支持的复核/拒绝流程及明确合法迁移；生产支付未接入时显示能力不可用，不展示虚构的“真实退款成功”。
- 恢复操作只能按原 command/reference/idempotency key 核对或继续既有状态机；UNKNOWN 不允许手工改成功、换键重付或直接释放不确定预占。没有安全恢复能力的命令只读展示并提供诊断引用。
- 商品、费率、收费配置的已发布版本保持不可变；编辑产生新版本，更新使用乐观锁/条件检查。发布预览显示受影响产品与未来购买行为，不重写历史订单。
- 产品声明、OIDC 回调/Origin、管理员引导、秘密配置的变更采用受控配置文件/工具发布；界面显示摘要、版本和校验结果。首版不新增浏览器秘密管理系统；计费配置在已有领域 API 内可编辑。

## 7. API、服务与存储结构

新增独立 `internal/platformadmin` 及 `internal/httpapi/admin_*.go`。Web 拆分到 `web/src/admin/`，避免继续将所有业务堆入 `App.tsx`。具体文件拆分由实施者决定，遵循已有 Go/React 与错误处理约定。

### 平台 API 族

| 接口族 | 职责 |
| --- | --- |
| `GET /admin/v1/me`、`/overview` | 当前平台角色、细粒度能力、能力未配置原因；指标及时间口径 |
| `/admin/v1/users`、`/users/{id}`、`/identity-directory` | 平台用户分页/详情与注册身份只读目录；显式用户创建/资料操作 |
| `/admin/v1/users/{id}/status`、`/sessions`、`/reset-requests` | 启停、会话查看/撤销、一次性重置；独立 action 权限 |
| `/admin/v1/admins`、`/admins/{id}/roles` | 平台管理员及角色版本管理 |
| `/admin/v1/accounts`、`/accounts/{id}/members`、`/invitations` | 跨用户账户查询及专门团队支持操作 |
| `/admin/v1/products`、`/users/{id}/product-access` | 声明/实例及用户产品授权 |
| `/admin/v1/api-keys`、`/calls`、`/usage-budgets` | 安全元数据与调用查询、Key 撤销及预算管理 |
| `/admin/v1/wallets`、`/recharges`、`/transactions` | 权威余额和账务链路查询，无直接余额写接口 |
| `/admin/v1/orders`、`/refunds`、`/subscriptions`、`/credit-batches` | 全局查询和已支持的退款复核；既有幂等恢复 |
| `/admin/v1/offers`、`/rates`、`/billing-profiles` | 平台财务授权下的领域操作适配 |
| `/admin/v1/audit-events`、`/system-status`、`/exports` | 审计、脱敏诊断、受限导出 |

列表固定采用有界 `limit`（默认 50、最多 100）与不透明游标；按 `(created_at,id)` 稳定排序，筛选/排序是游标绑定的一部分。返回 `items,next_cursor,total,as_of`。全站计数来自实际同筛选查询，不用当前页长度。身份提供方目录保持其自身分页能力，适配层不声称跨源事务快照。

所有写操作要求具体权限、真实 actor、目标范围、原因、预期版本；可重复提交的命令要求 `Idempotency-Key`。版本失配 409，未认证 401，无权限 403，功能未配置/上游不可用使用可区分的错误码；错误不泄露敏感存在性。读写目标由路由/校验结构绑定，不接受浏览器伪造权限或操作者。

平台浏览器会话使用现有 HttpOnly、SameSite Cookie 与 CSRF/Origin 检查；扩展 console 对 `/admin/v1` 的受保护转发和防缓存，不能落入 SPA 静态文件兜底。管理路由只接受中央控制台身份；产品 audience、模型/服务凭据都拒绝。每次请求查询当前用户状态及角色版本，撤权下一请求生效。

新增持久化包含：平台角色分配/版本/来源，用户认证活动与失效边界，一次性邀请/激活/重置请求，管理员幂等操作/上游待核对状态，worker 状态。复用已有用户、身份、产品授权、账户、Key 与账务记录。新增索引覆盖目录筛选、关联详情、未决状态和审计检索；不复制钱包余额或原生产品秘密。

现有 `/v1/user-management` 保留兼容，改为委托同一用户权限服务；旧权限不扩大。现有 `/ops/v1` 与产品 API 继续工作，不能因新增 Web 后台改变其 token 用途。

### 审计

统一查询现有 `product_user_audit`、`audit_events`、`billing_events` 并补新管理/团队/身份事件。保留原始来源和事件 ID，展示相同 actor/target/account/product/instance/request/operation 引用；不复制秘密，不把不同业务事件错误去重。

新本地变更与成功审计在同一事务提交；外部身份操作使用 durable intent → provider readback → success/failed/unknown 事件，未知结果不记录成功。授权拒绝与管理敏感读取/导出记录最少安全元数据；审计列表读取本身不递归生成无限事件。应用不提供审计修改/删除，未实施额外数据库控制前不宣称日志不可篡改。

### 切换与恢复

先执行新增表/索引迁移、只读覆盖核对和旧资格导入预览；显式应用导入和首位超管引导后读回权限，再开启平台入口。只增加表/列与兼容接口，不删除既有用户、授权、账务或会话记录以求切换。部署前保留数据库备份、配置摘要、源提交及还原演练记录。

回滚不能恢复已经撤销的权限、旧会话或 Key。旧二进制若只信任环境白名单、无法执行新角色/撤销边界，禁止直接回退并重新开放旧管理路由；优先使用保留安全校验的修复版本。必要时暂时关闭平台写入口，保留用户业务及可信结算/恢复，按受控工具恢复管理。不得用恢复整库覆盖新发生的真实资金操作；数据库恢复作为独立事故流程执行。

## 8. 统计口径与性能

- 用户总数指中央用户，身份提供方总数单列；启用/停用按查询时状态。团队数指 team 账户，不把个人账户计入。
- 最近登录从真实认证事件统计，旧记录缺失不回填成当前时间；首版不展示无可靠事件的“历史活跃用户”。
- 调用量按逻辑调用计数，attempt 另列；失败率排除仍在处理的调用，明确时间窗和时区；真实用量与供应商调用失败/取消分别展示。
- 收入只计已确认到账的支付事件，退款只计已确认完成，sandbox 独立标记/筛选。无真实支付能力时显示未接入，不显示测试收入为经营数据。
- 聚合记录 `as_of`、资产和筛选条件。列表按索引分页，详情按需加载关联页，禁止一次读取所有用户再在前端分页。上游目录/账本查询有超时、限流与明确部分失败状态。

## 9. 实施顺序与交付物

1. **权限与入口**：平台权限服务、显式引导、兼容旧管理员、能力接口、管理壳与稳定路由；修复入口错误状态和目录分页。以超管查看另一个用户为首个闭环；同时验证当前身份提供方的激活/恢复/会话撤销能力，及早完成必要适配。
2. **身份与账户**：完整目录、身份覆盖核对、用户详情/创建/资料/启停/重置/会话、管理员管理、账户/团队支持操作、产品授权。
3. **运营与财务**：Key/调用/预算、钱包账务、订单退款、订阅额度、商品费率/计费配置及现有安全恢复入口；复用领域状态机。
4. **可观测与验收**：概览、统一审计、导出、系统状态、配置说明；补齐端到端权限矩阵、失败/并发/回归与浏览器验收。

每批都包含后端权限、Web、审计、API 契约及对应验证，不交付有按钮无处理器的页面。最终同步 OpenAPI、接入/管理员引导文档、权限矩阵、运维恢复说明及可复现验收记录。部署版本、变更说明随实际可验证产物更新，不能用设计文件声称发布完成。

## 10. 必须通过的验收

1. **用户问题复现与闭环**：记录旧版当前账号的身份/能力响应及菜单；新版精确引导超管，浏览器看到至少另一名实际用户，进入详情并完成一次可回滚的管理变更，查到同一 actor 的审计，再读回。
2. **目录不漏人**：超过 100 名中央用户及至少一个仅注册未进入业务的身份；遍历分页不漏不重；搜索/状态/时间筛选与总数一致；上游不可用不能显示“没有用户”。
3. **完整业务路径**：创建普通测试用户 → 激活/登录 → 资料修改 → 加入/移出测试团队、转移 owner → 产品授予/撤销 → 查看 Key/调用与账务关联 → 停用/重新启用；各步骤读回与审计一致。
4. **角色矩阵**：超管、用户管理员、财务管理员、审计员、普通用户、团队 owner/admin、产品管理员、Casdoor isAdmin、产品 token、模型 Key、服务 token；逐类测试跨用户读取、写操作、导出及直接 API 越权。user_admin 不能管理平台管理员目标或读财务金额。
5. **末位保护与并发**：两个超管同时降权/停用、团队所有者并发移除、批量部分失败、旧版本保存都必须可预测；不能出现零可用超管或因成员变更导致零 owner。全局停用唯一启用 owner 时正确进入管理待恢复状态；所有权邀请撤权后不可接受。super_admin 与旧兼容资格/user_admin 并存时仍有完整超管能力，旧资格导入不能增加权限。
6. **凭据撤销**：已有控制台会话、产品 bearer、长期 Key 经停用立即不能发新业务；再启用后仍旧凭据失败，新登录有效；退出所有会话/密码重置后旧上游 SSO 或刷新路径不能免验证续接，失败状态不得显示完整成功。单独撤销会话不误撤其他团队成员 Key。权限撤销与到期下一次请求拒绝。
7. **资金/运营**：商品草稿发布、费率退役、计费配置冲突、订单与退款复核读回；现金/额度资产正确，模拟支付标签明确；无直接改账、重复交易或 UNKNOWN 强制成功。
8. **在途与恢复**：停用/撤权前已开始调用仍能由可信服务完成原结算和释放；不得二次扣款、切换账本或重付；恢复按原幂等键验证。
9. **失败与秘密**：身份创建/重置响应丢失、依赖断连、401/403/CSRF、审计失败、导出限额/公式注入；旧会话、重置链接、token/hash、秘密配置不出现在响应列表、URL 日志或持久存储。
10. **界面与回归**：管理深链刷新/返回、空/错误状态、窄屏基本可用，离开管理区保留账户选择；既有个人/团队、邀请、钱包、订阅及产品原生用户/登录/管理员/Key/余额/账本保持可用。UniHub 平台身份不自动获得原生产品 root。
11. **切换与回滚**：旧资格导入预览/执行/重复执行、零产品用户管理、生产身份能力门禁、最低安全版本检查与恢复演练。角色撤销和凭据失效不能在服务重启或二进制回退后恢复；无法安全回退时关闭平台写入口并保留可信结算。

数据库与账本相关测试必须在隔离的真实 PostgreSQL/Formance 环境实际执行，不能将缺少 `UNIHUB_TEST_DATABASE_URL` 导致的跳过当成通过。浏览器至少完成超管和普通用户的独立会话验收。
