# UniHub 统一产品管理员设计

状态：早期管理员专项草案。用户后续确认的范围已扩展为产品矩阵统一用户与可嵌入用户基础模块；以 [产品用户基础模块设计](2026-10-27-product-user-foundation-design.md) 为实施依据。本文件保留讨论背景，不再单独要求审批。

## 用户要求与结果

UniHub 应当支持注册用户，并为已接入的任意系统分配管理员身份。用户使用同一身份登录，在 UniHub 查看自己可管理的系统，进入对应后台；授权、降权、停用和审计均可追踪。

首个端到端接入目标为 LLMRouter。通用能力使用产品标识和角色定义，不将 LLMRouter 写死为唯一可管理系统。其他系统需接入身份与授权协议；未接入的外部系统不能凭注册记录自动获得可用管理账户。

## 当前源码与需要替代的约束

- `internal/accounts/store.go` 的 owner/admin/billing_admin/member 属于付费账户成员关系，不代表某个系统的运维权限。
- `internal/products/registry.go` 的 scopes 限制客户端可访问的 API，不表示当前登录用户是产品管理员。
- `internal/identityapi/server.go` 的普通注册固定创建 normal-user、isAdmin=false；保持自助注册不带管理员权限。
- `internal/auth/oidc.go` 当前只暴露已验证身份信息，没有通用产品管理授权。
- LLMRouter `model/unihub_identity.go` 强制普通身份投影无原生钱包、密码或管理权限；`middleware/auth.go` 另行限制原生路径。
- LLMRouter `internal/unihubaccess/policy.go` 与私有监听器保留原生运维边界，公网原生管理请求被拒绝。
- 2026-10-27 原身份计费设计仍适用于普通用户和原生应急通道；本设计新增 UniHub 管理会话，是对“管理员只能通过原生私有通道日常登录”的有意调整。历史验收记录保留。

## 方案选择

| 方案 | 优点 | 代价／边界 |
| --- | --- | --- |
| UniHub 统一用户与产品授权，各系统校验并执行（推荐） | 一处创建用户、授权、撤权和导航；系统范围明确 | 每个系统需要服务端授权适配 |
| 仅使用身份提供方的全局 isAdmin 标识 | 配置较少 | 无法准确表示某个产品的管理员，容易赋予过宽权限 |
| UniHub 为各系统分别创建本地密码账户 | 兼容缺乏单点登录的旧系统 | 密码、撤权和会话多处维护；只适合作为后续明确受限的旧系统连接器 |

选择第一项。Casdoor 继续作为身份提供方；UniHub 存储并判定产品管理授权；产品保留自己的业务后台与操作执行。

## 权限对象与边界

- 平台管理员：管理接入系统、用户生命周期、角色定义与用户授权。平台管理员资格不隐式产生所有产品的业务操作权限；需要显式产品授权。
- 产品管理员：某个用户在特定系统内被授予的管理角色。权限只在该系统及明确配置的实例范围生效。
- 团队管理员：既有付费账户内的成员管理角色，不能据此获得产品运维权限。
- 角色定义：隶属系统，包含明确权限集合、版本和可用状态；首版提供管理员与只读审计角色，LLMRouter 另有受控的高级配置角色。
- 授权：关联用户、系统／实例、角色、有效期、状态与版本，记录授权人、时间、理由和撤销信息。多个角色取已生效权限并集；未定义权限一律拒绝。
- 系统可以不配置钱包或收费规则。管理系统目录独立于既有计费产品表，并可显式关联；相同系统的多个实例必须使用不同范围，防止测试权限跨到生产。
- 产品管理员默认不获得全平台用户创建、跨系统授权或产品角色再分配权；首版授权操作集中由平台管理员完成。

普通注册、创建个人付费账户、成为团队 owner 均不会产生平台或产品管理员身份。身份关联使用已验证 issuer + subject，禁止按用户名或邮箱自动合并旧管理员。

## 用户与管理员操作流程

1. 平台管理员在 UniHub 的“系统与权限”注册系统／实例，配置精确回调地址、可信服务身份、管理入口和角色权限。
2. 在“用户管理”选择现有用户，或创建／邀请新用户。普通用户也可走产品已有策略允许的自助注册；注册本身不包含管理授权。
3. 选择系统与角色，设置有效期并确认授权；用户显示各系统的授权状态。
4. 用户用统一身份登录，在“我的管理系统”选择 LLMRouter，完成授权码与 PKCE 登录后进入渠道后台，无需另设产品管理密码或手动建立 SSH 隧道。
5. 管理请求由 LLMRouter 后端核对 UniHub 当前授权，按权限执行；导航可见性仅用于界面展示。
6. 平台管理员撤权或停用用户后，后续管理请求被拒绝，既有浏览器管理会话也不能继续操作。

用户创建采用已有身份提供方的受信任服务端连接，新增平台管理流程和用户目录查询；不复用允许自助注册的客户端策略去绕过管理员创建权限。激活采用用户设置密码的限时一次性流程，避免管理员向用户传递共享初始密码。发送邮件等通知需另外获得用户授权，开发和验收不向真实用户发送消息。

## 授权与登录协议

- 统一复用现有 OIDC 授权码／PKCE 身份流程，注册独立管理客户端及精确回调地址；产品后端建立独立管理会话。
- 登录凭据只证明身份。管理资格来自 UniHub 的实时授权判定，不从浏览器提交的 role、客户端 scopes、邮箱或 Casdoor 全局 isAdmin 推断。
- 管理会话与普通用户会话、模型凭据、产品服务凭据隔离用途和受众；不能互换使用。
- 产品后端使用该系统专属、受限的服务身份请求授权判定，服务端绑定 system_id／instance_id；产品不能以请求参数查询其他系统授权。
- 首版每次管理请求实时检查用户状态、会话状态、角色定义版本、授权状态、有效期与权限，无跨请求允许结果缓存。UniHub 不可达则拒绝管理请求。
- 权限检查前已经开始执行的操作不承诺回滚；撤权后的下一次授权判定必须拒绝。重要异步任务在真正执行前再次检查授权。
- 平台管理界面采用受保护的服务端会话与 CSRF 防护，所有授权变更使用并发版本检查和事务审计。

接口职责包括：受限的平台系统／角色／授权／用户管理、当前用户可管理系统查询，以及仅产品后端可调用的权限判定。具体路径随实现计划确定；所有身份从受验证的会话或服务身份取得。

## LLMRouter 首个适配

- 新增 UniHub 管理登录入口与服务端授权适配，公开暴露经过专用管理鉴权保护的渠道／账号池／诊断管理功能。
- 对全部 AdminAuth、RootAuth、RequirePermission 及其他管理入口建立可审阅的路由权限矩阵；未分类路由不得通过新管理通道。
- 管理员角色开放渠道、账号池和技术日志的明确操作；只读角色只开放相应查询；高级配置必须显式授权，不将普通产品管理员直接映射为不受限原生 root。
- 继续复用现有管理处理器与审计时，使用本次请求经验证的管理身份上下文，并保留统一用户标识。不能通过修改普通 UniHub 用户投影为永久本地 admin 来实现。
- 产品管理通道不开放原生本地钱包、充值、订阅、普通用户角色提升、原生 API key 签发与原生计费 relay。计费仍归 UniHub。
- 旧原生管理员及私有入口保留作应急与历史维护。迁移只建立明确审核的身份关联，不复制密码或自动合并资金；日常管理无需依赖旧账户。
- 产品管理操作和授权判定失败均留痕，现有依赖本地数字 user_id 的审计需要明确关联统一身份，不能将所有管理员记录为一个共享管理员。

## 引导与恢复

首位平台管理员通过受保护的部署工具将明确的 issuer + subject 设为引导管理员，记录审计与一次性初始化结果；不得采用首个注册用户自动提权或按用户名 admin 判断。新增平台管理员与撤销行为进入相同审计。

平台保护最后一位可用平台管理员，避免普通界面误操作导致全平台锁死。恢复使用受控服务器工具。现有 billing operator 的独立财务授权不由本次产品管理角色自动替换。

## 验收

1. 创建或选择一个 UniHub 用户，授权为 LLMRouter 管理员，用浏览器进入真实渠道后台，执行一次可回滚的管理变更并读回结果；不触发供应商调用或真实扣费。
2. 同一用户进入未获授权的第二系统／第二实例必须被拒绝；注册第二个测试系统证明通用模型无需增加 LLMRouter 专用字段。
3. 只读角色不能写；团队 owner/admin、普通注册用户、伪造 role、错误受众、错误产品服务凭据均不能进入管理操作。
4. 撤权、角色权限缩减、授权到期、用户停用和会话撤销均使已有浏览器的后续管理请求失效；UniHub 不可达不降级放行。
5. 管理授权不可签发模型调用凭据、修改余额或开放原生 relay；既有普通用户登录与统一计费回归通过。
6. 授权和实际管理操作审计能对应到同一个统一用户与系统／实例；并发授权冲突不能覆盖新版本。
7. 非授权用户不能自行提权；平台管理员资格变更、末位管理员保护、一次性引导与恢复路径均有实际验证记录。

分别记录自动化测试、本地浏览器验收、线上部署及真实管理员登录读回，不能以其中一项替代其他项。未完成接入的系统不声称已可管理。

## 交付顺序与当前边界

先实现通用系统目录、角色授权、平台用户管理界面与后端判定，再完成 LLMRouter 的管理登录／路由适配和完整浏览器验收。后续系统复用相同协议逐一接入。

本草案未授权线上创建真实管理员、修改现有用户权限、发送邀请通知或发布生产变更；当前不实施上述动作。新架构设计确认后编写实施计划。
