# 可组合收费实现验收

日期：2026-10-25（Asia/Shanghai）。本轮为用户明确提出的三类收费方式及组合配置提供实现；“充多少用多少”已确认直接扣人民币充值余额。

## 功能与兼容

- `hybrid`：会员订阅＋周期赠送额度＋加量包；年付逐月发放，额度用完不自动转扣现金。
- `prepaid`：无需会员，按真实计量消耗 llmrouter 产品钱包 CNY/6；来源产品现金、统一钱包和 CREDIT 批次均不作兜底。
- `subscription`：纯月/年功能会员，零赠送额度，不创建零数量账本交易，也不据此推断会员服务未使用并自动退款。
- 支持完整组件组合；双资产同时启用时，凭证使用显式选择或配置缺省，一次调用只有一种资产。财务汇总按资产分别计算。
- 收费配置与身份配置分离、按产品追加版本；同产品多个客户端共享配置。旧商品条款、已付年度权益、在途调用和 UNKNOWN 命令不重新计价。

## 实际执行的验证

真实隔离 PostgreSQL/Formance 上，全仓库 `go test -race ./...` 通过，随后针对最终审查修复重跑 billing/httpapi。显式启用 `UNIHUB_LLMROUTER_PATH` 的实际网关测试也在 race 下通过。前端27项、SDK12项测试及构建/类型检查通过；收费配置工具4项、部署收费配置11项、原部署11项、审计7项及身份资源回归通过。上游静态资源不存在时的一项可选资源检查会明确跳过，不把它计为已执行的浏览器验收。

真实 TCP HTTP 验收覆盖三个预设、月/年纯订阅续费、零额度不发放、人工核实退款、年付分月赠送、成员财务隐私、现金不足、现金/CREDIT费率不匹配、跨账户/钱包拒绝、预占/追加/释放/幂等结算、混合资产报表和签名游标。

实际 llmrouter → UniHub HTTP → PostgreSQL/Formance → 受控模型提供方接线结果：旧版会员路径扣20 CREDIT/6；无会员预付路径扣55 CNY/6。丢失一次真实结算响应后重启网关，收据恢复 SETTLED，供应商只派发一次，重复POST被拒绝，未重复扣款或扣网关本地quota。真实MySQL5.7、PostgreSQL9.6上的历史Call迁移均通过，临时容器已清理。测试中的模型供应商与OIDC验证是夹具，不代表真实商户或模型上游验收。详细复现见[网关集成说明](../integrations/llmrouter/README.md)。

## 独立审查与修复

1. 凭证签发在持有事务时二次获取连接会耗尽小连接池。新增可复用事务的授权检查，真实MaxConns=1回归从超时转为通过。
2. 直接把不受限的调用ID放入账本地址可制造永久UNKNOWN并阻塞账户。新现金预占固化独立命名空间的SHA-256地址，旧原始地址仍可追加/结算/释放；空格、符号、Unicode等不再污染账户。
3. 产品销售目录随收费配置过滤，原订单的相同幂等键重试曾被提前404。授权改为读取已发布商品的不可变归属，新销售仍执行配置检查；已付款订单恢复重新通过。
4. 该归属查询进一步排除可改归属的草稿，封闭“并发移动草稿后跨产品扣款”的窗口。移除过滤的独立复现会购买到外国产品；当前实现拒绝该请求。
5. CNY与CREDIT报表只提供各币种总额，混合结果不返回误导的单一金额。普通成员没有 charged/held/钱包字段。

以上问题均有失败复现和修复后的定向回归。最终独立审查未发现剩余资金、跨模式或隐私阻断项。

## 交付边界

变更在独立开发分支中实现，配置/API/SDK/示例客户端和部署工具齐备。现有公网v0.1.0及其标签未改动，本轮没有配置真实支付商户、正式价格或更换线上产品收费规则。llmrouter的通用升级提供可审阅补丁，并已在本机隔离集成检出验证；线上网关仍须按其发布流程升级。

接入产品仍自行实现界面与业务判断；示例用户中心的本地自动化检查不等于公网浏览器验收。新版配置/代码部署前，应按标准流程保留备份，显式发布收费配置版本，再复核实际身份、网关与账本链路。
