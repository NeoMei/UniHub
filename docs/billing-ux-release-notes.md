# UniHub 计费与三方接入体验补全

## 已完成

- 账户控制台新增“套餐与用量”页，集中展示当前方案、月付/年付方案、模型额度、统一钱包、待处理订单和账单入口。
- 正式环境读取 `/v1/capabilities`；`real_payments_configured=false` 时仍可查看商品和用量，但购买按钮会禁用并解释原因。
- 购买确认增加付费账户、服务期限、额度发放、退款规则和资金来源说明。
- 订单状态分开显示付款和权益发放；`PENDING`、`UNKNOWN`、人工核实状态提供刷新和账单读回入口，避免重复提交。
- 钱包页增加人民币元单位说明、测试环境提示、充值快捷金额和 UNKNOWN 操作提示；统一钱包划拨与测试充值保持分开。
- 平台后台支持编辑 BillingProfile 的订阅、赠送额度、加量包、按量、订阅前置、资金模式、默认资金模式和模型白名单。
- 商品草稿支持编辑权益键值、退款规则和升级规则，仍由服务端版本与校验规则最终裁决。
- 平台后台新增“三方接入工作台”，可生成最小权限 scopes、计费组合和服务端执行命令；浏览器不保存客户端密钥。
- 方案卡片、钱包快捷操作和后台接入工作台增加移动端布局、键盘焦点和可访问名称。

## 验证结果

- Web Vitest：57 个测试通过。
- Web production build：TypeScript 构建与 Vite 构建通过。

## 仍需运营验收

- 真实支付机构、生产 OIDC 客户端、正式费率和供应商结算仍需部署侧配置与真实回读；代码完成不等于支付已经开通。
- 沙盒充值和 `sandbox-settle` 只验证流程，不产生真实到账。
- 三方接入工作台输出的是准备计划；密钥登记、生产部署、回调连通性和正式业务验收仍由接入方服务端完成。

## 账户财务界面简化（2026-11-05）

- 个人主导航收敛为账户概览、产品会员、模型余额与充值、账单和模型消费。套餐与用量、权益额度、加量包、支付自动化、我的应用及团队功能保留在“更多账户功能”；个人账户显示“团队与邀请”，团队账户显示“团队成员”。平台管理入口只有在平台资格核验成功后显示，直达管理地址仍走原有权限检查。
- 概览、套餐与用量及钱包页分别展示 `llmrouter` 托管模型人民币余额和 `superwagie` 会员购买余额。统一钱包和其他产品余额可展开查询；CREDIT 明确标为会员/加量包权益资产，使用范围按现有 BillingProfile 显示，不按余额推断可抵扣模型。
- 保留 `view=wallets&product=llmrouter|superwagie`、`view=memberships&product=superwagie`、`view=consumption`、`view=bills` 和 `view=user-management` 任务链接。登录前的提示可在本标签页保留到登录后；钱包产品必须与已加载目录精确匹配，未核验的产品不自动改充其他钱包。切换任务不会把钱包提示带入消费来源筛选。
- 消费页的 `product` 仅表示 `origin_product_id`，资金钱包仍由记录中的 funding 字段单独说明。默认展示时间、模型、产品、扣费和状态，原付款账户、完整编号、资产标识、预占与价格信息在每行“查看调用详情”中保留。非财务角色不显示金额，即使浏览器收到多余财务字段也隐藏。
- 原始实扣与返还分开，人民币、CREDIT 和旧原生额度按资产分别展示，微元与大整数精度不变。UNKNOWN、尚未结算、请求失败、缺失值及确认的零余额保持不同状态。
- 测试充值与可选手动划拨分成独立表单和确认步骤，原请求格式不变。真实收款未配置提示、测试标记、UNKNOWN 恢复、自动授权默认关闭均保留。切换付款账户或财务角色会销毁旧确认状态。
- 模型钱包提供 SuperWagie 托管连接设置指引；LR 原生 API Key 仍在 LR 原生控制台管理，余额不能证明凭据或模型可用性。

### 隔离 UI 复核

先执行 `npm --prefix web ci` 和 `npm --prefix web run build`，再运行 `node scripts/settings-ui-fixture.mjs 4187`。服务仅监听 `127.0.0.1`，完全使用生成记录，没有生产代理或凭据，并拒绝所有非 GET 请求。

- `http://127.0.0.1:4187/`：个人概览，模型现金 12.345678 元、会员现金零、CREDIT 5、统一钱包与其他产品余额。
- `http://127.0.0.1:4187/?fixture=admin`：相同财务数据和已核验的平台管理员入口。
- `http://127.0.0.1:4187/?view=wallets&product=llmrouter`：预选模型钱包；展开可选手动划拨，确认窗口可核对目标，但 fixture 拒绝提交。
- `http://127.0.0.1:4187/?view=wallets&product=superwagie`：预选会员钱包。
- `http://127.0.0.1:4187/?view=wallets&product=missing`：未知产品保持未确认，须明确选择后才能准备充值。
- `http://127.0.0.1:4187/?view=consumption`：独立现金/CREDIT/旧额度、返还、UNKNOWN 及原付款账户详情。
- `http://127.0.0.1:4187/?fixture=member&account=B&view=consumption`：团队普通成员消费，金额隐藏。
- `http://127.0.0.1:4187/?fixture=error&view=wallets&product=llmrouter`：钱包失败，不显示零余额。将 view 换为 consumption 可检查调用与摘要失败。

这些场景仅验证界面显示和交互，不证明真实支付、真实模型调用、后台业务集成或生产验收。

本次本地验证：目标四文件 56 项、全量 Web 110 项通过；TypeScript 与 Vite 构建通过。隔离 UI 结果不能替代生产支付或模型调用验收。
